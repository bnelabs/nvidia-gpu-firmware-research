# Generation Matrix — NVIDIA Consumer GPU Firmware (Pascal → "RTX 60")

## TL;DR
- Every modern card runs four firmware layers: **vBIOS** (boot-time policy), **GSP firmware** (RISC-V runtime brain, Turing+), **engine-falcon microcode** (PMU/SEC2/NVDEC/NVENC), and the driver-side RM control plane.
- GSP images ship *inside every driver package*: a single `gsp.bin` until ~555, then per-arch `gsp_tu10x.bin` / `gsp_ga10x.bin` under `/lib/firmware/nvidia/<driver-version>/` [GitHub issue 62](https://github.com/NVIDIA/open-gpu-kernel-modules/issues/62), [NVIDIA 595 README](https://download.nvidia.com/XFree86/Linux-x86_64/595.104.02/README/gsp.html).
- Kernel-module policy split: Pascal and older = **closed-only**; Turing→Ada = **both** (open recommended); Blackwell = **open mandatory** [NVIDIA dev blog](https://developer.nvidia.com/blog/nvidia-transitions-fully-towards-open-source-gpu-kernel-modules/).
- There is **no** `gsp_ad10x.bin`: the `ga10x` image covers Ampere *and* Ada (AD102 boards load `gsp_ga10x.bin` [NVIDIA forum log](https://forums.developer.nvidia.com/t/nvidia-corporation-ad102gl-l20-loading-lib-firmware-nvidia-580-95-05-gsp-ga10x-bin-failed-with-error-4/379900)).
- vBIOS signature enforcement (Turing→Ada era) was broken in 2023 by OMGVflash/NVflashk [TechPowerUp](https://www.techpowerup.com/312631/nvidia-bios-signature-lock-broken-vbios-modding-and-crossflash-enabled-by-groundbreaking-new-tools); Pascal is the tail of the unsigned-nvflash era.
- Maxwell/Pascal/Volta end feature support with the R580 branch [TechPowerUp](https://www.techpowerup.com/338497/nvidias-v580-driver-branch-ends-support-for-maxwell-pascal-and-volta-gpus); Turing continues on the open KMD.

## Reading the firmware column (per generation)

- **Acquisition points**: vBIOS from the [TechPowerUp vBIOS Database](https://www.techpowerup.com/vgabios/) or `nvflash --save`/GPU-Z; GSP images from the NVIDIA `.run` package (`firmware/` dir), distro packages (e.g. Debian/Ubuntu `nvidia-firmware-*`), or the [NVIDIA linux-firmware fork](https://github.com/NVIDIA/linux-firmware) / [kernel-firmware MRs](https://gitlab.com/kernel-firmware/linux-firmware/-/merge_requests/52) (Nouveau path).
- **Versioning**: the GSP image version must match the driver version (`nvidia-smi -q` → `GSP Firmware Version`; also in `/proc/driver/nvidia/gpus/<busid>/information`) [NVIDIA README](https://download.nvidia.com/XFree86/Linux-x86_64/595.104.02/README/gsp.html). Rig ground truth @ 615.71.09: `gsp_ga10x.bin` 27,043,992 B, `gsp_tu10x.bin` 22,897,536 B [rig dump](06-ground-truth/dumps-20261015-122221/gsp-firmware-images.txt).
- **Disable switch**: `NVreg_EnableGpuFirmware=0` forces the pre-GSP code path on Turing→Ada (no effect on Blackwell, which has no closed module) [NVIDIA README](https://download.nvidia.com/XFree86/Linux-x86_64/595.104.02/README/gsp.html).
